# สถิติผู้เล่นและนาทีลงสนาม

แท็บ “ข้อมูล NBA” → “สถิติผู้เล่นจาก NBA” ดึง Per Game จาก LeagueDashPlayerStats
หรือรับ NBA JSON / HTML ที่มีตารางแสดงผลจริง รองรับฤดูกาลปัจจุบันและ Regular Season ฤดูกาลก่อน
เลือก season/type ให้ตรงกับไฟล์ ไม่มีการแอบเปลี่ยน Preseason เป็น Regular Season
หาก NBA endpoint timeout ให้ใช้ไฟล์ที่บันทึกจากหน้า NBA แทน ไม่มี proxy/retry bypass

## เมื่อดึงสดไม่ได้

แท็บ **ข้อมูล NBA → สถิติผู้เล่นจาก NBA → ฐานสถิติผู้เล่น** เลือกได้แยกจากประเภทเกมที่วิเคราะห์:

- **Preseason ฤดูกาลที่เลือก**: มีสถิติ 2026–27 ที่เตรียมไว้ 577 แถว
- **Regular Season ฤดูกาลก่อน**: มีสถิติ 2025–26 จากหน้า NBA จำนวน 582 แถว
- **ฤดูกาล/ประเภทที่เลือก**: ใช้เมื่อมีข้อมูลของฤดูกาลใหม่แล้ว ไม่ย้ายป้าย Preseason เป็น Regular Season

ข้อมูลที่บันทึกไว้แสดงทันที ไม่ต้องกดดึงซ้ำ หากกดดึงแล้ว NBA ติดต่อไม่ได้ ข้อมูลเดิมยังอยู่
หรืออัปโหลด NBA JSON/HTML ที่มีตารางแสดงผลจริง โดยเลือกฤดูกาล/ประเภทให้ตรงกัน
หลังบันทึกใหม่ให้กลับแท็บวิเคราะห์แล้วกด **ใช้เวลาปัจจุบัน** เพื่อให้ as-of ครอบคลุมข้อมูลใหม่นั้น

## รายชื่อผู้เล่นของทีม

แยกรายชื่อจากสถิติทีมแล้ว จึงเลือกทีม/โหลดรายชื่อได้แม้ยังไม่มีเกม Regular Season
เตรียมรายชื่อจากหน้า NBA ของทั้ง 30 ทีม รวม 518 คน ณ วันที่ 20 ต.ค. 2026 ใน `deployment/roster_cache/`
แต่ละทีมมีเวลาอ่าน URL ต้นทาง และ hash อ้างอิง ไม่ใช่การรับรองรายชื่อ ณ นาทีปัจจุบัน
หน้าวิเคราะห์ใช้สำเนาที่มีให้ทันที และแสดงวันที่ของรายชื่อทั้งสองทีม
ข้อมูลที่ใหม่กว่าในฐานข้อมูลมีลำดับก่อนสำเนา; ไม่ใช้สำเนาที่อ่านหลังเวลา as-of
หากฐานข้อมูลเชื่อมต่อไม่ได้ยังแจ้งข้อผิดพลาดตามเดิม ไม่แอบเปลี่ยนที่เก็บประวัติ

ในแท็บข้อมูล NBA เลือก **ทีมที่ต้องการรายชื่อผู้เล่น** แล้วกด **ดึงรายชื่อผู้เล่น** เพื่ออัปเดตจากหน้า NBA
หรืออัปโหลด NBA roster JSON / HTML จากหน้า team ที่มีตาราง Roster จริง
รายชื่อที่เตรียมไว้โหลดตามทีมที่เลือก ไม่ส่งทั้ง 30 ทีมไปฐานข้อมูลทุกครั้งที่เปิดแอป
หลังมีการย้ายทีม/เซ็นสัญญาควรตรวจรายชื่อที่ NBA อีกครั้งก่อนเลือกตัวจริง

เก็บ GP, MIN, PTS, REB, AST, STL, BLK, TOV, FGM/FGA, 3PM/3PA, FTM/FTA และ +/-
คำนวณ eFG% และ TS% (ใช้ 0.44 สำหรับ FTA โดยเป็นค่าประมาณ) เมื่อมี attempts เท่านั้น
ไม่มี attempts แสดงค่าว่าง ไม่สร้างเปอร์เซ็นต์ศูนย์ขึ้นแทน
player ID + team ID เป็นคีย์ของแต่ละแถวเพื่อเก็บ stint ของผู้เล่นที่ย้ายทีม

แท็บวิเคราะห์มี “สถิติผู้เล่น / นาทีลงสนาม / ผลกระทบต่อทีม”
จับคู่รายชื่อด้วย player ID โดยค้นฤดูกาล/ประเภทที่เลือกก่อน ตามด้วย Regular Season ฤดูกาลก่อน
และ Preseason ปีเดียวกันเมื่อทำนาย Regular Season เลือก stint ทีมตรงก่อน total แล้วแถวที่มี GP มากสุด
แสดงฤดูกาล/ทีมต้นทางและ snapshot ID โดยไม่สมมติว่าคนที่ไม่มีข้อมูลเป็นผู้เล่นผลงานศูนย์

## การปรับ probability

สถิติ box score ไม่ใช่ค่าผลกระทบส่วนบุคคล จึงไม่แปลง PTS หรือ +/- เป็นแต้มได้เปรียบอัตโนมัติ
ต้องเลือก “ใช้เรตติ้งผลกระทบและนาทีที่กำหนดเอง” แล้วระบุแหล่งเรตติ้ง
ตารางให้แก้ baseline minutes, expected minutes และ offense/defense impact ของแต่ละคน
นาทีฐานตั้งต้นจาก MIN ที่มีและ normalize 240 ต่อทีม; คนที่ขาดข้อมูลเริ่มจากน้ำหนัก 12 นาที
ชุดฐานนี้เป็นการประมาณ ต้องแก้ให้ตรงกับ rotation ที่สร้างเรตติ้งทีมเดิม โดยเฉพาะเมื่อมีการย้ายทีม
ค่าผลกระทบเริ่มที่ 0 (เป็นกลาง) ไม่ใช่ค่าฝีมือที่ระบบประเมินไว้แล้ว

impact มีหน่วยแต้มต่อ 100 possessions; offense บวกคือทำแต้มดีขึ้น defense บวกคือช่วยลดแต้มคู่แข่ง
ระบบปรับเฉพาะส่วนต่าง `(นาทีคาดการณ์ − นาทีฐาน) / 48` เพื่อไม่บวกความสามารถผู้เล่นซ้ำกับทีม
บังคับนาทีฐานรวม 240 และจำกัด 0–48 ต่อคน; นาทีคาดการณ์ normalize 240 ในกลุ่มที่เลือกลง
รายชื่อที่ไม่ติ๊กลงจะไม่ถูกจัดนาที รุ่นนี้คงการรับ scenario JSON สำหรับผู้เล่นไม่แน่ใจไว้ด้วย
ไม่ใช้ JSON ขั้นสูงร่วมกับตารางปรับผู้เล่นในครั้งเดียว (JSON มีลำดับความสำคัญสูงกว่า)

โมเดลยังเป็น experimental และไม่ผ่าน holdout จริง แม้กรอกสถิติ/impact ครบ
การไม่มี impact ratings ไม่ได้ขัดขวางการวิเคราะห์ระดับทีม แต่ probability จะไม่เปลี่ยนจากชื่ออย่างเดียว
